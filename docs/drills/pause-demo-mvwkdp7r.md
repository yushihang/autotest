# 暂停/恢复演练记录（pause → resume，`e2e-pause-mvwkdp7r`）

> **状态：已结束（2026-10-31）。** 这是一次演练的存档：只记录当时发生了什么，不描述产品行为，也不构成任何规则。与其它文档冲突时，以其它文档为准——本文件没有优先权。

## 目的

验证一条链路：任务跑到一半被暂停（pause）之后，恢复（resume）时能从暂停点继续把交付走完，而不是从头再来或者直接丢掉这次运行。观察三件事：

- 暂停之后，这次运行还能不能被恢复；
- 恢复之后，交付是否照常落到 PR 分支上；
- 恢复的那一轮是否守住了「勿改业务代码」的边界。

## 这份演练证明了什么、没证明什么

- **证明了**：一次被暂停的 intake 运行可以被恢复；恢复后交付照常走完，改动确实落了 PR 分支；恢复的那一轮没有越界去改业务代码。
- **没有证明**：暂停期间的状态被**完整**保存。本次唯一产物是一行标记，恢复后要做的事与暂停前完全一致，所以「接着上次继续」和「从头再来一遍」在结果上不可区分——这条演练分不出两者。
- **没有证明**：带未完成副作用的运行恢复后不会出问题。比如已经写了一半的文件、已经推了一半的分支，恢复时会不会重复写入或丢失，这次没有触及。要验证那一点，需要一次在交付中途暂停、且暂停点前后都有实际文件变更的演练。

一句话：这次证明的是**链路通**，不是**状态被正确保存**。链路通不等于恢复语义正确。

## 为什么文件名带运行 ID、为什么放在 `docs/drills/`

这两点不是格式偏好，是这条演练本身暴露出来的约束：

- **文件名带运行 ID**：暂停演练是并行跑的。同一批里另有 `#82`（`e2e-pause-mvwk1505`）和 `#87`（`e2e-pause-mvwk6zv5`），当时三者的产物都叫根目录的 `pause-demo.md`、内容各是各自的行。任何一个先合，后合的都会冲突；就算不冲突，后合的那个也会把上一次的运行 ID 覆盖掉——演练证据就此丢失。带上运行 ID，几次并行演练才能并存。
- **放在 `docs/drills/`**：仓库根目录只留 `README.md`，其余文档都在 `docs/`。这一点此前已经纠正过一次：`ac1a616` 把根目录的 `followup-demo.md` 删掉、改成 `docs/followup-demo.md`。本文件沿用同一约定，不再往根目录放标记文件。
